## FNC-001 ログインする

### 目的と利用者

すべての利用者が、このシステムを使い始めるときにログインする。本人であることを確かめ、その利用者の役割を後の操作で使えるようにする。

### 業務ルール

- FR-001 利用者は、社員番号とパスワードを入れてログインする。
- FR-001-AC-01 前提: 登録済みの利用者で、ロックされていない。操作: 正しい社員番号とパスワードでログインする。結果: メニューの画面が出る。
- FR-002 社員番号かパスワードが誤っているとき、ログインできない。ログイン画面に共通のエラーの文を出す。
- FR-002-AC-01 前提: 登録済みの利用者。操作: 誤ったパスワードでログインする。結果: ログインできず、ログイン画面にエラーの文が出る。
- FR-002-AC-02 前提: 登録のない社員番号。操作: その社員番号でログインする。結果: ログインできず、FR-002-AC-01 と同じエラーの文が出る。
- FR-003 同じ社員番号でパスワードを続けて 5 回誤ったとき、その社員番号を 15 分ロックする。
- FR-003-AC-01 前提: パスワードを続けて 5 回誤った。操作: 15 分のうちに正しいパスワードでログインする。結果: ログインできず、FR-002-AC-01 と同じエラーの文が出る。
- FR-003-AC-02 前提: ロックから 15 分が過ぎた。操作: 正しいパスワードでログインする。結果: ログインでき、誤った回数は 0 に戻る。
- FR-004 ログインに成功したとき、それまでの誤った回数を 0 に戻す。
- FR-005 ログインの状態は、操作のない時間が 30 分を超えると切れる。
- FR-006 ログインの状態は、ログインから 8 時間を超えると、操作を続けていても切れる。
- FR-006-AC-01 前提: ログインの状態が FR-005 か FR-006 で切れた。操作: メニューの画面を開く。結果: ログイン画面に移る。
- FR-007 ログインしていない人がログインの要る画面を開くと、ログイン画面に移る。
- FR-007-AC-01 前提: ログインしていない。操作: メニューの画面を開く。結果: ログイン画面に移る。
- FR-008 ログインしていない人がログインの要る API を呼ぶと、401 を返す。
- FR-008-AC-01 前提: ログインしていない。操作: メニューを返す API を呼ぶ。結果: 401 が返る。
- FR-009 ログイン中の利用者を返す API は、社員番号・氏名・部署・役割を返す。
- FR-009-AC-01 前提: 上長と社員の役割を持つ利用者でログインした。操作: ログイン中の利用者を返す API を呼ぶ。結果: 社員番号・氏名・部署と、2 つの役割が返る。
- FR-010 パスワードは平文で保存しない。保存するのは復元できない形(ハッシュ)だけにする。
- FR-010-AC-01 前提: 初期データを入れた。操作: DB の利用者のテーブルを読む。結果: 平文のパスワードはなく、ハッシュだけがある。
- FR-011 ログイン画面とメニューの画面は、パソコンとスマホのブラウザで使える。
- FR-011-AC-01 前提: 画面の幅が 375px のブラウザ。操作: ログインし、メニューを見る。結果: 横にはみ出さずに操作できる。

### 例外と境界

- 社員番号かパスワードが空のときは、API を呼ばずにログイン画面で入力を求める。
- ロック中の社員番号に正しいパスワードを入れても、誤った回数は増やさない。
- ロック中も、ロックの理由を画面に出さない。登録のある社員番号かを推し量れないようにするためである。
- 同じ利用者が複数のブラウザで同時にログインできる。

### 扱うデータ

- 利用者
- 役割
- 部署

### 設計で足す予定のデータ項目

- 社員番号
- 氏名
- パスワードのハッシュ
- 誤った回数
- ロックの終わる時刻

### この機能だけの非機能の要件

- パスワードとログインの状態の扱いは、非機能要件の NFR-005〜NFR-008 に従う。
