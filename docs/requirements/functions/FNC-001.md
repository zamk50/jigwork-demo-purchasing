## FNC-001 ログインする

### 目的と利用者

すべての利用者が、このシステムを使い始めるときにログインする。本人であることを確かめ、その利用者の役割を後の操作で使えるようにする。

### 業務ルール

- FR-001 利用者は、社員番号とパスワードを入れてログインする。社員番号は数字 6 桁である。
- FR-001-AC-01 前提: 登録済みの利用者で、ロックされていない。操作: 正しい社員番号とパスワードでログインする。結果: メニューの画面が出る。
- FR-002 社員番号かパスワードが誤っているとき、ログインできない。ログイン画面に共通のエラーの文を出す。
- FR-002-AC-01 前提: 登録済みの利用者。操作: 誤ったパスワードでログインする。結果: ログインできず、ログイン画面にエラーの文が出る。
- FR-002-AC-02 前提: 登録のない社員番号。操作: その社員番号でログインする。結果: ログインできず、FR-002-AC-01 と同じエラーの文が出る。
- FR-003 登録済みの社員番号でパスワードを続けて 5 回誤ったとき、その社員番号を 30 分ロックする。
- FR-003-AC-01 前提: パスワードを続けて 5 回誤った。操作: 30 分のうちに正しいパスワードでログインする。結果: ログインできず、FR-002-AC-01 と同じエラーの文が出る。
- FR-003-AC-02 前提: ロックから 30 分が過ぎた。操作: 正しいパスワードでログインする。結果: ログインできる。
- FR-004 誤った回数は、ログインに成功したときと、ロックが終わったときに 0 に戻る。
- FR-004-AC-01 前提: ロックから 30 分が過ぎた。操作: 誤ったパスワードで 1 回ログインする。結果: ロックされず、続けて 4 回誤るまでログインを試せる。
- FR-004-AC-02 前提: パスワードを続けて 4 回誤った。操作: 正しいパスワードでログインし、ログアウトして、誤ったパスワードで 4 回ログインする。結果: ロックされない。
- FR-020 ロック中のログインは、パスワードの正誤によらず誤った回数に数えず、ロックの終わる時刻も延ばさない。
- FR-020-AC-01 前提: ロック中。操作: 誤ったパスワードで 3 回ログインし、ロックから 30 分が過ぎた後に正しいパスワードでログインする。結果: ログインできる。
- FR-005 ログインの状態は、操作のないまま 30 分を超えると切れる。
- FR-005-AC-01 前提: ログインし、30 分を超えて操作しなかった。操作: メニューの画面を開く。結果: ログイン画面に移る。
- FR-006 ログインの状態は、ログインから 8 時間を超えると、操作を続けていても切れる。
- FR-006-AC-01 前提: ログインから 8 時間を超えた。30 分を超えて操作が途切れたことはない。操作: メニューの画面を開く。結果: ログイン画面に移る。
- FR-007 ログインしていない人がログインの要る画面を開くと、ログイン画面に移る。
- FR-007-AC-01 前提: ログインしていない。操作: メニューの画面を開く。結果: ログイン画面に移る。
- FR-008 ログインしていない人がログインの要る API を呼ぶと、401 を返す。
- FR-008-AC-01 前提: ログインしていない。操作: メニューを返す API を呼ぶ。結果: 401 が返る。
- FR-009 ログイン中の利用者を返す API は、社員番号・氏名・部署・役割を返す。
- FR-009-AC-01 前提: 上長と社員の役割を持つ利用者でログインした。操作: ログイン中の利用者を返す API を呼ぶ。結果: 社員番号・氏名・部署と、2 つの役割が返る。
- FR-010 パスワードは平文で保存しない。保存するのは復元できない形(ハッシュ)だけにする。
- FR-010-AC-01 前提: 初期データを入れた。操作: DB の利用者のテーブルを読む。結果: 平文のパスワードはなく、ハッシュだけがある。
- FR-011 ログイン画面とメニューの画面は、パソコンとスマホのブラウザで使える。
- FR-011-AC-01 前提: 画面の幅が 375px のブラウザ。操作: ログインし、メニューを見る。結果: 横にはみ出さずに操作できる。
- FR-021 社員番号かパスワードが空のときは、API を呼ばずにログイン画面で入力を求める。
- FR-021-AC-01 前提: ログイン画面。操作: パスワードを空のままログインする。結果: ログインの API は呼ばれず、パスワードの入力を求める文が出る。
- FR-024 数字 6 桁でない社員番号は、ログイン画面で止め、API を呼ばずに形の誤りを出す。API に直接来たときは、FR-002 と同じ失敗にする。
- FR-024-AC-01 前提: ログイン画面。操作: 社員番号に 5 桁の数字を入れてログインする。結果: ログインの API は呼ばれず、社員番号の欄の下に形の誤りの文が出る。
- FR-024-AC-02 前提: なし。操作: 数字 6 桁でない社員番号でログインの API を直接呼ぶ。結果: 401 と、FR-002-AC-01 と同じ誤りの文が返る。
- FR-022 同じ利用者が、複数のブラウザで同時にログインできる。
- FR-022-AC-01 前提: ブラウザ A でログインした。操作: ブラウザ B で同じ利用者でログインし、両方でメニューの画面を開く。結果: 両方でメニューの画面が出る。

### 例外と境界

- 登録のない社員番号は、何度誤ってもロックしない。誤った回数を持つ利用者がいないためである。エラーの文は FR-002 と同じである。
- ロック中も、ロックの理由を画面に出さない。登録のある社員番号かを推し量れないようにするためである。
- ロックは、ロックから 30 分たった時刻に終わる。その時刻ちょうどのログインは、ロック中として扱わない。
- ロックの時間を変えたとき、変える前にかかったロックは、かかったときに決まった終わる時刻に終わる。

### 扱うデータ

- 利用者
- 役割
- 部署

### 設計で足す予定のデータ項目

- 社員番号
- 氏名
- パスワードのハッシュ
- 誤った回数
- ロックの終わる時刻

### この機能だけの非機能の要件

- パスワードとログインの状態の扱いは、非機能要件の NFR-005〜NFR-008 に従う。
- 画面の幅は、非機能要件の NFR-010 に従う。
