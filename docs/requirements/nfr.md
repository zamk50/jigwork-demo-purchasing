# 非機能要件

## 可用性

定めない。稼働の時間と止めてよい時間は、本番に配置する Issue で決める。

## 性能・拡張性

- NFR-001 ログインとメニューの表示は、それぞれ 1 秒以内に終わる(仮定。依頼元の「重く感じない」を数にした)。
- NFR-002 利用者は約 120 人、部署は 3 つを前提に作る。

## 運用・保守性

定めない。運用の手順は、本番に配置する Issue で決める。

## 移行性

- NFR-003 紙と Excel からのデータの移行は、この範囲では行わない。利用者・役割・部署は初期データで入れる。

## セキュリティ

- NFR-004 認証は自前の社員番号とパスワードで行う。外部のクラウドの認証は使わない。
- NFR-005 パスワードは、復元できないハッシュの形で保存する。
- NFR-006 秘密の情報(DB の接続先・ログインの状態の鍵・初期データのパスワード)は、リポジトリに置かない。環境変数から読む。
- NFR-007 DB の接続先かログインの状態の鍵が無いとき、API のサーバーは起動の時に止まる。
- NFR-008 ログインの状態は、操作のない 30 分か、ログインから 8 時間で切れる。
- NFR-009 リポジトリを秘密を探す道具(gitleaks)で走査すると、指摘が 0 件である。

## システム環境・エコロジー

- NFR-010 画面は、パソコンとスマホのブラウザで使える。スマホでは幅 375px を下限とする。
- NFR-011 DB のすべてのテーブルと列に、日本語の論理名のコメントを付ける。テーブルにはテーブル番号(例 T001)を付ける。
