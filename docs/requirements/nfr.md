# 非機能要件

## 可用性

定めない。稼働の時間と止めてよい時間は、本番に配置する Issue で決める。

## 性能・拡張性

- NFR-001 利用者 1 人が操作したとき、ログインとメニューの表示はそれぞれ 1 秒以内に終わる。🟡 依頼元の「重く感じない」を数にした仮定である。確かめ方: 画面の通しのテストで、手元の PC で時間を測る。
- NFR-002 利用者は約 120 人、部署は 3 つを前提に作る。確かめ方: 設計で、この人数のときのログインの状態の数と DB の行の数を見積もる。

## 運用・保守性

定めない。運用の手順は、本番に配置する Issue で決める。

## 移行性

- NFR-003 紙と Excel からのデータの移行は、この範囲では行わない。利用者・役割・部署は初期データで入れる。確かめ方: 空の DB に初期データを入れるだけで、4 役割の利用者がログインできる。

## セキュリティ

- NFR-004 認証は自前の社員番号とパスワードで行う。外部のクラウドの認証は使わない。確かめ方: 依存の一覧と設定に、外部の認証のサービスがない。
- NFR-005 パスワードは、復元できないハッシュの形で保存する。
- NFR-006 秘密の情報(DB の接続先・ログインの状態の鍵・初期データのパスワード)は、リポジトリに置かない。環境変数から読む。
- NFR-007 DB の接続先かログインの状態の鍵が無いとき、API のサーバーは起動の時に止まる。
- NFR-008 ログインの状態の切れ方は、FR-005 と FR-006 のとおりである。
- NFR-009 リポジトリに秘密の情報がない。確かめ方: 秘密を探す道具でリポジトリを走査し、指摘が 0 件である。

## システム環境・エコロジー

- NFR-010 画面は、パソコンとスマホのブラウザで使える。スマホでは幅 375px を下限とする。
- NFR-011 DB のすべてのテーブルと列に、日本語の論理名のコメントを付ける。テーブルにはテーブル番号(例 T001)を付ける。
