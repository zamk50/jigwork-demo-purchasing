# 方針決めの要約(Issue 42 ログインのロックが掛かったことを、ログで見分けられるようにする)

- 段階は重要(major)と判定した。因子は「利用者から見える仕様の変更」(visible)と「認証・認可・個人情報」(auth)である。
  - auth の根拠: ログインの判定の業務の層(`authenticate`)の振る舞いを変え、ロック中であることをログに出す。
  - visible の根拠: 運用の担当が読むログに新しい種類の行が出て、要件 FNC-001 に FR を足す。
- 因子の再判定は auth だけを該当とし、visible を非該当とした(画面と API の応答は変わらないため)。下げる向きの食い違いなので visible を残した。どちらでも段階は重要で、通すフェーズは同じである。
- 省くフェーズはない。要件定義で FR を足し、設計(auth のため省けない)で区別の渡し方とログの文言・水準を決める。
- 依頼元の答え: 行を出すのは「ロックが掛かった時」と「ロック中の試み」の 2 つ。ロックの解除の行は入れない。
- 仮定のまま残る前提(🟡)は 2 つある。ログを読むのは運用の担当だけであること。運用の担当は決まった語の検索でロックの行を見つけること。
- 推奨から外した所はない。
- 機械レビュー(通常、品質と整合): 必須の指摘は 0 件である。
  - 推奨 7 件と参考 4 件は plan.md に反映した。
  - 主な直しは、型を変えると断定しない書き方と、受入基準 AC-03 に役割なしと形の誤りを足したことである。
- 要件定義に引き継ぐ点: 5 回目の誤りとロック中の試みで、ロックの行に加えて「ログインに失敗した」の行も出すかを決める。
