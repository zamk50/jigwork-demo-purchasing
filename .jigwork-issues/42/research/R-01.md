# 調査メモ R-01(Issue 42「ログインのロックが掛かったことを、ログで見分けられるようにする」)

調査役(jig-investigator)が方針決めで調べた結果である。事実と推測を分けて書く。

## 要約

- 事実: 「ログインに失敗した」の行は `backend/app/api/auth.py:138` の 1 か所だけで、INFO 水準で出る。
- 事実: サービスの層の `authenticate`(`backend/app/auth/service.py:101-145`)は `User | None` だけを返す。ロックが掛かった瞬間(134-135)・ロック中の試み(123-127)・ふつうの失敗は、どれも `None` になる。API の層はこれらを区別できない。
- 事実: 外への応答は、どの失敗も 401 と共通の文である。ロックの理由を画面に出さないのは要件である(`docs/requirements/functions/FNC-001.md:50`)。ログだけを分けるには、戻り値・例外・状態のどれかに区別を足す変更が要る。応答の形は変えない。
- 事実: テーブル・画面・API の形・設定の変更は要らない。既存の列 `locked_until` と `failed_login_count` で足りる。
- 事実: ログを定める要件の ID(FR・NFR)は無い。ログの決まりは方式設計 `docs/internal/architecture.md:97-106` だけにある。

## 1. 今のログの出し方

- 失敗の行は `backend/app/api/auth.py:137-139` の `logger.info("ログインに失敗した 社員番号=%s", ...)` である。ロガーは `app.auth`(34 行)。
- 成功の行は 144 行の `logger.info("ログインに成功した 社員番号=%s", ...)` である。
- 社員番号は `_employee_no_for_log`(105-107)で整える。数字 6 桁なら値を出し、そうでなければ「形の誤り」と出す。
- 書式は `%(asctime)s %(levelname)s %(name)s %(message)s` で、標準出力に出す。ロガー `app` の下は INFO 以上を出す(`backend/app/log.py:26,29-35`)。
- `authenticate` が `None` を返す道筋は次の 5 つである。
  - 数字 6 桁でない(114-116)
  - 登録なし(119-121)
  - ロック中(123-127。ダミーのハッシュで照合し、列は変えない)
  - 誤ったパスワード(132-136)。5 回目で `locked_until` を設定する(134-135)
  - 役割なし(138-140)
- 事実: `authenticate` の呼び出し元は `auth.py:136` の 1 か所だけである。
- 実現方法の候補(推測。方針決めと設計で決める):
  - (a) `authenticate` が理由を持つ結果(列挙型など)を返す。
  - (b) サービスの層がログを出す。ただし `service.py` は今ログを出さず、ログの出口は API の層にそろっている。
  - (c) 呼び出しの前後で `locked_until` を比べる。

## 2. ログに出してはいけないもの・要件

- 方式設計 `docs/internal/architecture.md:103` は「ログインの成否と社員番号は残し、パスワードとログインの状態の印は残さない」と定める。
- 数字 6 桁でない社員番号は値を出さず「形の誤り」と書く(`architecture.md:104`)。
- ロックの要件:
  - FR-003(5 回誤ると 30 分ロック。`FNC-001.md:17`)
  - FR-004(回数が 0 に戻る条件。`FNC-001.md:20`)
  - FR-020(ロック中は数えず、延ばさない。`FNC-001.md:23`)
  - 補足(`FNC-001.md:49-52`): 登録のない社員番号はロックしない。ロック中の理由を画面に出さない。
- 注意: ロックの行は、その社員番号が登録済みであることをログに出す。ログは運用の担当が読むもので、利用者への応答ではない。登録のない社員番号はロックしないので、ロックの行も出ない。

- テスト: 5 節のとおり。

## 4. 同じ作り・同じ原因の箇所

- アプリのログの出力は `backend/app/api/auth.py`(失敗 138・成功 144)と `backend/app/api/errors.py:44`(想定しない例外)だけである。
- 登録なし・形の誤り・誤ったパスワード・役割なし(FR-023)も、同じ「ログインに失敗した」の 1 行である。
- ロックの解除(`service.py:128-130`)と、ログインの状態の切れ(`service.py:167-179`)は、ログに何も出ない。
