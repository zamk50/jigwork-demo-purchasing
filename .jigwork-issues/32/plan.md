# Issue 32 README に仕様概要 docs/spec.md への案内を書く

## 方針決め

### 理解の要約

- 何を: `README.md` に、仕様概要 `docs/spec.md` への案内を 1〜3 行で書き足す。案内には、何の文書か・どこにあるか・相対リンクを含める。
- なぜ: README から仕様概要の文書へたどれるようにするため。
- どこまで: README に書き足すだけ。今ある README の文、コード、`docs/spec.md` は変えない。

### 前提の一覧

確かめた前提:

- `README.md` は今 3 行(見出し・空行・説明の 1 文)。
- `docs/spec.md` はリポジトリにある(Issue #29 で入った)。先頭の見出しは「架空の会社「みなと精機」の、備品・消耗品の購買と在庫のシステム」。
- 入力の正本は GitHub の Issue #32 の本文。添付はない。

仮定のまま残る前提:

- 🟡 案内は README の末尾(今の説明の文の後)に、空行を 1 つ挟んで足す。小見出しは付けない。違っても置き場を動かすだけで済む。
- 🟡 リンクは Markdown の相対リンク `[docs/spec.md](docs/spec.md)` で書く。違ってもリンクの書き方を直すだけで済む。

### 受入基準

- AC-1: `README.md` に `docs/spec.md` への相対リンク(`](docs/spec.md)`)が 1 つ以上あり、リンク先のファイルがリポジトリにある。
- AC-2: 足した案内は 1〜3 行(空行を除く)で、「仕様概要」の語(何の文書か)と、`docs/spec.md` の文字列(どこにあるか)をどちらも含む。
- AC-3: 今ある README の文は変わっていない。基準のコミット(/base で決めた `c217adb7e7`)からの `git diff` で、`README.md` の差分が追加の行だけ(削除・変更の行がない)である。
- AC-4: この Issue の差分は文書だけである。基準のコミットからの `git diff --stat` で、`README.md` と `.jigwork-issues/32/` のほかに変わったファイルがない(jig が書く記録 `.jigwork/records/` は除く)。`docs/spec.md` が変わっていない。

### スコープ外

- 今ある README の文を直す・並べ替えること。
- `docs/spec.md` の中身を変えること。
- README にほかの案内(使い方・構成など)を足すこと。
- コードを書くこと。

### 段階の判定

| 因子 | 判定 | 根拠 |
|---|---|---|
| 意図の抜け | 非該当 | Issue が対象(`README.md`)・中身(何の文書か・どこか・相対リンク)・行数(1〜3 行)・制約(既存の文・コード・spec.md を変えない)を書いている |
| 利用者から見える仕様の変更 | 非該当 | アプリはまだなく、動く物を変えない |
| データ構造の変更・データ移行 | 非該当 | DB もデータもない |
| 認証・認可・個人情報 | 非該当 | 案内の文だけで、個人情報を含まない |
| 外部連携 | 非該当 | 外部のサービスにつなぐ物を作らない |
| 約束・予算・期限への影響 | 非該当 | personal の既定でオフ |
| 影響範囲の広さ | 非該当 | README に 1〜3 行を足すだけ |
| 新しい作り・依存 | 非該当 | 依存を足さない |

判定: **軽微(minor)**。差分の 1 文: 「README に仕様概要 `docs/spec.md` への案内を足す」。
