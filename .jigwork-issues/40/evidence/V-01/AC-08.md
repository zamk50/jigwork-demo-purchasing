# AC-08 定数を 15 分に戻すと落ちる(FR-003。テスト項目 TC-08)

基準: 実装の定数 `LOCK_DURATION` を 15 分に戻してテストを流すと、`backend/tests/test_i40_lock_duration.py` の `test_i40_tc08_lock_duration_is_30_minutes` が落ちる。

## 確かめ方

製品のコードを直さないため、リポジトリの作業ツリーは触らず、HEAD の `backend/` を検証役の一時の置き場(scratchpad)に書き出して、その写しの定数だけを戻した。

```
git -C <repo> archive --format=tar -o <scratchpad>/ac08/backend.tar HEAD backend
tar -xf ... -C <scratchpad>/ac08
sed -i 's/^LOCK_DURATION = timedelta(minutes=30)$/LOCK_DURATION = timedelta(minutes=15)/' <scratchpad>/ac08/backend/app/auth/service.py
grep -n '^LOCK_DURATION' app/auth/service.py
→ 43:LOCK_DURATION = timedelta(minutes=15)

cd <scratchpad>/ac08/backend && <repo>/backend/.venv/bin/python -m pytest -p no:cacheprovider --import-mode=importlib -v tests/test_i40_lock_duration.py
→ rootdir: <scratchpad>/ac08/backend
→ tests/test_i40_lock_duration.py::test_i40_tc08_lock_duration_is_30_minutes FAILED
→ E assert datetime.timedelta(seconds=1800) == datetime.timedelta(seconds=900)
→ 1 failed
```

- 比べた右辺が 900 秒(15 分)なので、写しの定数を読んでいる。

対照として、リポジトリの HEAD(定数 30 分)で同じテストを流した。

```
cd backend && .venv/bin/pytest -p no:cacheprovider --import-mode=importlib -v tests/test_i40_lock_duration.py
→ test_i40_tc08_lock_duration_is_30_minutes PASSED、1 passed
```

- 実行の後、`git status --short` は `.jigwork/records/issues/40/log.jsonl` だけで、製品のコードは変わっていない。
- 実装の記録でも、赤のコミット 114edec(「実装 T-2: ロックの時間が 30 分であることのテストを足す」)が jig の `red` として記録されている(common-test-run.md の seq 263)。

## 判定

合格。
